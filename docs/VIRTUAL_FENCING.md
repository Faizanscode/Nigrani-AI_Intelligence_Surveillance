# Virtual Fencing and Intrusion Detection

## Overview
Virtual Fencing is Step 5 of the IBVAP (Intelligent Border Video Analytics Platform). It provides software-defined security boundaries over a camera view to detect unauthorized entry into restricted zones. 

This module consumes `TrackResult` generated by the YOLO + ByteTrack/BoT-SORT tracking layer and evaluates the real-time position of objects against configured geometric polygons.

**Note:** Virtual fencing detects geometric boundary crossings. It does NOT determine intent or whether an individual is hostile.

## Fence Polygon Format
Fences are defined as a list of 2D coordinates `(x, y)` representing a closed polygon. Polygons must contain at least 3 points and can take arbitrary shapes (e.g., triangle, quadrilateral, complex convex/concave shapes). The geometry is evaluated using OpenCV's `cv2.pointPolygonTest`.

Example:
```json
"polygon": [
    [100, 100],
    [800, 100],
    [900, 500],
    [200, 600]
]
```

## Point Selection Strategy
By default, the engine uses the **bottom-center point** of the object's bounding box as the evaluation point. This represents the object's approximate point of contact with the ground, providing highly accurate evaluations for border walls or restricted ground zones compared to using the bounding box center.

This is configurable via `FENCE_POINT_STRATEGY` in the `.env` file.

## Crossing Logic & State Management
The system tracks the geometric state of every object relative to every enabled fence.

* **OUTSIDE → INSIDE**: Triggers an `IntrusionEvent` (direction="ENTRY").
* **INSIDE → INSIDE**: Ignored. Prevents duplicate events while the object remains inside.
* **INSIDE → OUTSIDE**: Does not trigger an event. Updates internal state back to OUTSIDE.
* **UNKNOWN → INSIDE (Initial Observation)**: If an object appears for the very first time already inside the fence, it does **not** trigger an event by default (configurable via `TRIGGER_ON_INITIAL_INSIDE`).

### Boundary Behavior
If an object lands exactly on the boundary (`cv2.pointPolygonTest == 0`), the engine retains the object's previous state. This prevents flickering/duplicate alerts if the object oscillates exactly on the line.

## Event Model
When an intrusion is detected, a structured event is generated. These events are exposed to the pipeline metadata and will be consumed by the future Alert Engine (Step 6).

```json
{
    "event_id": "evt_abc123",
    "event_type": "VIRTUAL_FENCE_INTRUSION",
    "camera_id": "cam_001",
    "fence_id": "fence_001",
    "track_id": 17,
    "object_class": "person",
    "confidence": 0.93,
    "timestamp": 1699999999.123,
    "position": {"x": 420, "y": 510},
    "direction": "ENTRY",
    "severity": "HIGH",
    "status": "NEW"
}
```

## Multi-Camera and Multi-Fence Isolation
The `FenceEngine` runs independently for each camera pipeline. 
* A single camera can have multiple active fences (e.g., a Border Zone fence for persons, and a No-Vehicle Zone fence for cars).
* A single `track_id` crossing multiple fences will generate independent events for each.
* Track IDs and states are completely isolated between cameras to prevent cross-camera collisions.

## Configuration
The following variables can be configured in `.env`:
* `VIRTUAL_FENCE_ENABLED=true`: Enable/disable the entire fence engine.
* `TRIGGER_ON_INITIAL_INSIDE=false`: Set to `true` to trigger an event if an object is first detected already inside the fence.
* `FENCE_POINT_STRATEGY=bottom_center`: The bounding box reference point used for geometric testing.

## REST API
Provides endpoints to manage fences dynamically. Fences are evaluated in real-time as they are added or removed.

* `GET /api/v1/cameras/{camera_id}/fences`: List fences
* `POST /api/v1/cameras/{camera_id}/fences`: Create fence
* `DELETE /api/v1/cameras/{camera_id}/fences/{fence_id}`: Delete fence

## Limitations
* Currently relies on in-memory storage for fences. Restarts will clear configured fences. Step 6 / Database integration will add persistence.
* Tracks are cleared when the pipeline restarts; cross-session intrusion state persistence is not implemented yet.
