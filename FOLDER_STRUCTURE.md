# Directory Structure

```text
IBVAP/
├── backend/                  # FastAPI application
│   ├── app/
│   │   ├── api/              # REST API routers and endpoints
│   │   ├── core/             # Configuration (settings), security (auth), dependencies
│   │   ├── db/               # SQLAlchemy models, DB sessions, Alembic migrations
│   │   ├── services/         # Business logic, Alert Engine, Camera Manager
│   │   └── main.py           # FastAPI entry point
│   ├── requirements.txt
│   └── .env.example
├── ai_engine/                # Independent AI Processing Subsystem
│   ├── ingestion/            # Video stream handlers (File, Webcam, RTSP)
│   ├── detection/            # YOLO models and ObjectDetector wrappers
│   ├── tracking/             # Object trackers (ByteTrack)
│   ├── analytics/            # Virtual fence, ANPR, FRS, Loitering logic
│   ├── models/               # Downloaded model weights (pt, onnx) - gitignored
│   └── pipeline.py           # Orchestrator tying ingestion -> detection -> tracking -> analytics
├── frontend/                 # React/Vite application
│   ├── src/
│   │   ├── components/       # Reusable UI components (VideoPlayer, AlertCard)
│   │   ├── pages/            # View pages (Dashboard, Settings, Login, History)
│   │   ├── services/         # API clients (axios), WebSocket handlers
│   │   └── App.jsx           # Main React component and Router
│   ├── index.html
│   ├── package.json
│   └── vite.config.js
├── data/                     # Local storage (not tracked in Git)
│   ├── videos/               # Sample MP4 files for testing and initial prototyping
│   └── snapshots/            # Saved images generated by the Alert Engine
├── tests/                    # Project tests
│   ├── backend/              # Pytest API tests
│   ├── ai_engine/            # Unit tests for CV algorithms
│   └── frontend/             # Vitest frontend tests
├── docs/                     # Documentation (Architecture, API specs, schemas)
├── README.md                 # Project README
└── docker-compose.yml        # Future containerization orchestration
```

## Directory Purposes:
- `backend/`: Solely responsible for serving REST APIs, managing database connections, and WebSockets. It does not run deep learning inference directly.
- `ai_engine/`: Completely isolates heavy computer vision tasks from the web server. Its modular structure allows easy swapping of models without breaking the backend.
- `frontend/`: The presentation layer providing the central surveillance dashboard to end users.
- `data/`: Local storage for evidence (snapshots) and inputs (MP4 files). Keeps media out of the source code.
- `tests/`: Automated testing suites organized by subsystem.
- `docs/`: Holds architectural diagrams, roadmaps, and specification files.
